## 零、一页纸结论

我要做四件事：

| # | 做什么 | 一句话理由 |
|---|---|---|
| 1 | 把两个工作副本同步，并明确「哪个是开发区、哪个只是仓库本体」 | 现在主仓库停在 06-02，落后 5 个提交，谁在主仓库打开就改旧代码 |

## 二、第一部分：目录清理

### 目标状态

```
D:/AIdocument/lg1/waiguoren1          ← 仓库本体（只存 .git 和同步后的文件，不开编辑器改代码）
C:/Users/.../main-4d15d3f8            ← 唯一开发区（WorkBuddy 在这里干活）
```

### 具体做法

1. **同步主仓库**：在主仓库执行 `git pull --ff-only`，从 `3947271` 追平到 `249a227`。纯快进，不产生新提交，不动 C 盘。
2. **清理主仓库的两个未跟踪项**：
   - `laowaitown-logo-creative-v2.png`（2.6 MB，未使用）→ 删除
   - `.qoder/plans/全站视觉统一重设计_b1a1ec58.md` → 归入 `docs/archive/qoder/plans/`
3. **主仓库的 `node_modules/`、`public/`**：两者都已在 `.gitignore` 里，保留不动（`public/` 是上次构建产物，可留着，也可删，重跑 `npm run build` 即恢复）。
4. **写进交接文档的红线**：以后只在 C 盘 worktree 改代码；D 盘目录不得移动或删除。

**为什么不干脆只留一个目录？** 因为 worktree 的设计就是"一个 .git + 多个工作区"，删掉主仓库等于把 .git 也删了。真正的收敛方式是「明确分工」，不是「物理合并」。物理合并需要重建仓库历史，风险和收益完全不匹配。

## 五、第四部分：开发工作流

### 一条路径，五个关卡

```
① 说需求   →  ② 改代码   →  ③ 跑自检   →  ④ 提交   →  ⑤ 推送并验证线上
 （模板1）      （只改C盘）    npm run build   （模板2）    push → 等 2 分钟 → curl 确认
```

每一步都有明确的"做完的标志"，不靠感觉：

| 关卡 | 命令 / 动作 | 通过标志 |
|---|---|---|
| ① 说需求 | 用模板 1 描述 | 目标、范围、禁区、验收标准四项齐全 |
| ② 改代码 | 在 C 盘 worktree 内编辑 | `git status` 只出现预期文件 |
| ③ 自检 | `npm run build` | 8 类校验全绿，无 `Missing publish file` |
| ④ 提交 | 用模板 2 写 message | 钩子放行，`git log -1` 可读 |
| ⑤ 上线 | `git push origin HEAD:main` | 2 分钟内线上可见变化 |

### 模板 1：需求描述模板（你发给 AI）

```
【目标】一句话说清要解决什么问题
【范围】只改这些：<文件 / 页面>
【禁区】不要动：shared/visa-data.js、legal/、构建脚本、Cloudflare 配置
【验收】我怎么判断做对了：<可观察的结果>
【参考】风格参照：<某个已有页面>

先只读不写，把你打算改的文件和改法列出来，我确认后再动手。
```

最后那句是**关键**。它把「AI 猜 → 改错 → 返工」变成「AI 说计划 → 你点头 → 一次做对」。

### 模板 2：提交信息模板

```
<type>(<scope>): <中文说明> / <English>

type:  feat 新功能 | fix 修 bug | content 内容 | data 政策数据 | chore 杂务 | docs 文档
scope: homepage | visa | life | legal | shared | scripts | ci
```

示例：
```
feat(visa): 新增 3 个 240h 过境路线页 / add 3 transit route pages
content(life): 更新支付宝绑卡流程 / update Alipay card binding steps
fix(homepage): 修复国籍下拉在移动端被截断 / fix country dropdown cutoff
```

### 模板 3：新页面模板

沿用 `docs/page-template.md`，我会把它补成「复制即用」的完整骨架（含必备的 `lw-sources` 官方来源区块，否则 `check-site.js` 会拦）。

### 模板 4：AI 会话开场模板

已在 `docs/ai-handoff.md` 第 8 节，届时会把「只改 C 盘 worktree」这条补进去。

### 可选增强（默认不做，等你同意）

- `.github/workflows/check.yml`：push / PR 时自动跑 `npm run build`，让校验从"自觉"变成"门禁"
- 分支约定：`main` 生产，`feat/xxx` 开发，合并前必须过检查

**我的意见**：CI 值得做，但建议放在整理完成、你的操作习惯稳定之后再上。现在加，你还没建立起"每次推之前跑一次 build"的肌肉记忆，加了也只是摆设。

## 七、执行顺序（4 步，每步独立可验收、可回滚）

| 步骤 | 内容 | 耗时 | 风险 | 回滚 |
|---|---|---|---|---|
| **Step 1** | 主仓库 `git pull --ff-only` 追平；删 2.6MB 未用图；`.qoder/plans` 归档 | 5 分钟 | 极低（纯快进 + 删未跟踪文件） | 无需回滚 |
| **Step 2** | 文档归位：`git mv` 根目录 5 篇 + `.qoder` 全部 → `docs/archive/`；迁出 `protected-data.md`；改钩子注释 | 20 分钟 | 低（只有移动，内容不变） | `git revert` 单个提交 |
| **Step 3** | 删 A 级冗余（`index-v1-backup.html`、`mockups/`、残留 gitignore 规则）；建 `docs/README.md` | 15 分钟 | 低 | `git revert` |
| **Step 4** | 补写模板 1-3 成"复制即用"版；更新 `ai-handoff.md` 加入双副本红线 | 20 分钟 | 无（纯新增/改写文档） | `git revert` |

每一步单独提交、单独推送。**Step 2 和 Step 3 各推到线上一次，但都不会改变任何页面的渲染结果**（移动和删除的都是不发布的文件）。

全部做完后跑一次 `npm run build` + 线上抽查 3 个页面，确认零影响。

## 九、我不建议做的事（说明理由，避免以后反复讨论）

| 不建议 | 理由 |
|---|---|
| 把两个目录物理合并成一个 | 需要重建仓库历史；worktree 的正确用法就是"一个 .git 多个工作区"，分工清楚即可 |
| 用 Next.js / React 重写 | 58 个页面已被搜索引擎收录，重写等于丢掉排名；你缺的是内容和信任，不是框架 |
| 删掉 `.qoder/rules/protected-data.md` | 这是项目唯一的数据审批制度，要迁走而不是删掉 |
| 现在就加 CI + 分支保护 | 会在你还没形成固定操作习惯时增加摩擦，建议整理稳定后再上 |
| 清空 `.workbuddy/memory/` | 那是跨会话的项目记忆，删了等于每次重新认识项目 |
| 重命名 `📚文档导航.md` 后放进 docs/ | 它导航的是那 5 篇教程，一起归档即可，不必抢救 |
